# 调试功夫

与诊断闭环（bug-diagnosis-loop，先建紧反馈回路再修）互补：这个管**怎么科学地找到根因**。

## 心态

科学方法五步循环：**观察**实际行为 → **假设**可能原因 → **实验**验证 → **分析**证据 → 重复到根因。

三不假设：「不可能是 X」（可能就是）、「我没改过 Y」（查了再说）、「我机器上是好的」（查清为什么）。卡住就歇——大脑后台还在跑。

## 四阶段

**1. 复现**
稳定复现是一切的前提。问三件事：必然还是偶发？特定条件？别人能复现吗？然后做**最小复现**：删到不能再删，问题还在。

**2. 取证**
- 完整堆栈与错误码、日志全文
- 环境（系统/运行时/依赖版本）
- **最近改了什么**（git 历史、部署时间线、配置变更）
- 波及面（所有用户还是特定用户？所有环境还是只有生产？）

**3. 假设**
基于证据问：什么变了？好的与坏的差在哪？链路上哪一环可能失败（校验/逻辑/数据/外部服务）？一次只立一个假设。

**4. 验证**
- **二分**：注释掉一半代码（或 git bisect 找引入提交），缩小范围到锁定
- **加痕**：在关键路径打日志追变量与执行流
- **隔离**：单独测每个组件，mock 掉依赖
- **对照**：好的环境与坏的环境逐项 diff

## 高级技巧

- **git bisect**：标记好/坏提交，自动二分历史，数分钟锁定引入点；完了 `bisect reset`。
- **差分调试**：列「工作 vs 故障」差异表（环境、版本、数据量、用户、时间），最可疑的差异先验证——「只在午夜后坏」指向时区/定时任务。
- **追踪**：给可疑函数包一层追踪（入参、返回值、耗时），看数据怎么变形。

## 专项打法

**间歇 bug**：怀疑竞态与顺序依赖——狂加重试/压力跑、记录全部状态转移与外部交互、查并发访问的共享状态、查异步完成顺序。
**性能问题**：先剖析再动手（同性能优化技能铁律），常见嫌犯：N+1 查询、同步 IO、大数据全量处理。
**生产 bug**：日志与监控先行、只读诊断（别在生产调试）、找等价环境复现、必要时空段降级。

## 卡住了，按序自查

假设验证了吗（还是只是「看起来对」）？最小复现做了吗？最近一次「好的」到「坏的」之间 diff 过吗？问题真的在那一层吗（往上往下再探一层）？换双眼睛看过吗？

## 收尾

根因修复后必补回归测试（诊断闭环的铁律）；把「这次的弯路」按复盘技能沉淀成自动检查。
