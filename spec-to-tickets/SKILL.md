# 规格拆工单

把一份规格/计划/会话拆成**曳光弹工单**：每张都是打穿所有层（数据、逻辑、界面、测试）的窄而完整的纵切片。

## 流程

**1. 收上下文**：吃透会话或指定材料（规格全文、评论、决策记录）。

**2. 摸代码库**（可选但推荐）：工单措辞用项目词汇表、尊重既有决策；顺手找**预因子化**机会——「先让改动变容易，再做那个容易的改动」。

**3. 起草纵切片**，每张满足：

```
- 窄但完整：打穿每一层，绝不横向只切一层
- 单独可验收：这张做完能演示或能验证
- 一窗能装：单张工单塞得进一个全新上下文窗口
- 预因子化前置：需要铺垫的改动排最先
```

每张工单声明**阻塞边**：必须先完成哪些工单。无阻塞 = 可立即开工。

**宽重构例外**：一个机械改动波及全库（改列名、改共享类型），纵切片无法落绿 → 走**扩张-收缩**：先扩张（新旧形态并存）→ 分批迁移调用点（每批一张工单，阻塞于扩张，CI 全程绿，因旧形态还在）→ 收缩（删旧形态，阻塞于全部迁移批）。

**4. 向用户过目**：编号列表逐张列「标题 / 阻塞于 / 交付什么」，问三件事——粒度对吗（太粗/太细）、阻塞边对吗、要不要并/拆。迭代到认可。

**5. 发布**：逐张发布（阻塞者在前），阻塞边落到追踪器的原生依赖关系；无追踪器则一工单一文件按依赖顺序编号。发布后按**前沿**推进：阻塞全清的工单随时可领。

## 工单模板

```
# NN〈工单标题〉

**做什么**：这张工单交付的端到端行为（用户视角，不是分层实现清单）。

**阻塞于**：前置工单编号/标题；无则写「无，可立即开工」。
```

## 红线

- 工单描述写行为，不写实现步骤清单——实施者自己定路径。
- 不动父规格/父问题，只增工单。
- 线性链以外必有并行前沿：能用上并行的拆法优先。
