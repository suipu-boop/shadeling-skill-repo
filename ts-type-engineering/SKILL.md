# TS 类型工程

TS 类型系统的价值 = **把运行时错误搬进编译期**。高级类型不是炫技，是让「改字段名/加状态」这类重构由编译器兜底。

## 四板斧分工

| 工具 | 用途 | 典型场景 |
|---|---|---|
| **泛型** | 类型参数化的可复用组件 | 容器/API 封装/带约束的工具函数（`extends` 约束） |
| **条件类型** | 按输入类型分支推导 | `T extends X ? A : B`、`infer` 提取返回值/数组元素类型 |
| **映射类型** | 逐键变换现有类型 | Readonly/Partial 变体、按类型过滤键、key 重映射（`as`） |
| **模板字面量类型** | 字符串模式级约束 | 事件名（`on${Capitalize<E>}`）、路径类型、受限字符串 |

标准组合拳：映射 × 模板字面量 = 「把 User 变成 { getName: () => string, ... }」这类派生 API 类型；条件 × infer = 从既有函数类型反推参数/返回值。

## 类型编程的克制（重要度不亚于会用）

- **能推导就不手写**：TS 推导很强，处处显式标注 = 噪音。
- **嵌套条件类型 > 2 层要警觉**：编译器变慢、同事看不懂——超了就拆成中间命名类型，或退回运行时判断。
- **递归类型限深**：递归 mapped type 是编译性能杀手，路径类工具控制在真实需求深度。
- 复杂类型**加注释说明意图**——类型也是代码，也有读者。
- **`any` 换 `unknown`**：unknown 强制收窄后使用，`any` 是类型系统停运开关。

## 编译期保障的日常纪律

- `strict: true` 全开（strictNullChecks 是其中价值最大的一项）。
- **可辨识联合**（discriminated union）管理互斥状态：`type State = { t: 'loading' } | { t: 'ok', data: D } | { t: 'err', e: E }`——switch 穷尽检查让漏处理状态在编译期报错，**比布尔标志组合安全一个量级**。
- 少用类型断言 `as`：断言 = 「我比编译器懂」——大概率是自欺；用类型守卫（is）替代。
- `satisfies` 校验而不改变推导：配置对象「符合形状但保留字面量精度」两全。

## 类型测试

关键工具类型配类型级断言（`Expect<Equal<A, B>>` 惯用法）+ `@ts-expect-error` 标注「这里必须报错」——类型库自身的重构安全网。

## 收尾清单

strict 全开 / any 清零（unknown+收窄）/ 可辨识联合管状态 / 断言少用 / 复杂类型有注释有中间名 / 类型测试兜底 / 嵌套条件克制。
