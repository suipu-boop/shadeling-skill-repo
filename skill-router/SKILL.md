# 流程路由地图

记不住所有流程时查这张图。**主流程**是最常见的路径，**岔路**是特殊情况下的入口，**阶段边界**是每段工作收尾时的选择。

## 主流程：想法 → 交付

1. **磨想法**：用追问访谈把模糊想法磨清楚。有工作目录就用带留痕版（词汇表、决策记录落盘），没有就用无状态版。
2. **分岔判断一：问题能否纸上定案？** 若需要跑起来才知道（状态、业务逻辑、界面手感）→ 先做一次性原型回答问题，再用交接文档把结论带回主流程。
3. **分岔判断二：是否多会话工程？**
   - **是** → 会话成规格 → 规格拆工单 → 逐单实施（每单开新上下文）或整包实施
   - **否** → 直接在当前上下文实施
4. 实施以**测试先行**驱动（一轮红绿一块），收尾做**双轴代码审查**（规范轴 + 规格轴）。
5. 发 PR 时填三件套：最小可视图、生效证据（前/后）、单双向门判断。
6. **复盘**收口：翻看本次会话，把机械性失误变自动检查、判断性分歧变规范条文——改进的是环境，不是代码。

**上下文纪律**：磨想法、成规格、拆工单保持在同一连续上下文里（互相依赖同一份思考）；每张工单的实施另起新上下文；复盘在被复盘的会话内做。

## 三类岔路入口

- **问题/请求堆积** → 走分诊流程：把原始诉求加工成代理可执行的工单。注意：自己拆出来的工单已就绪，不要再分诊。
- **东西坏了** → 走诊断闭环：先建「一跑就红」的紧反馈回路，再修，补回归测试。若根因是缺好接缝，转架构普查。
- **大雾工程**（太大、看不清路）→ 走迷雾寻路：先画决策地图、逐个解决决策，路清了再并入主流程的「会话成规格」。不要拿寻路直接当实施用。

## 代码库保养（非功能工作）

架构普查随时可跑：找出值得深化的模块，产出深化机会清单；选中的机会作为新想法进入主流程。

## 阶段边界五选项

一段工作结束、下一段开始前，有五个选项：

| 选项 | 何时选 |
|---|---|
| 继续 | 上下文还有余量、下一段强依赖当前思路 |
| 清空 | 当前内容对下一段毫无价值 |
| 交接文档 | 要换目录/换会话/交同事/中途分岔——买的是可携带性 |
| 子代理 | 把边界内一段紧定义的任务派出去，拿报告回来 |
| 压缩 | 默认兜底：压缩上下文并以摘要开启新会话 |

先排除「继续」以外的惯性——接近上下文极限时不要硬撑降级推理，在最近阶段边界压缩或交接。

## 独立件

- **无状态访谈**：不在工作目录时磨计划/设计/文章用。
- **原型**：一次性代码回答一个设计问题（逻辑手感 or 界面长相），答案折回真实代码。
- **背景调研**：派后台代理读一手资料，产出带引用的笔记文件，喂回主流程。
- **问卷**：堵点在别人脑子里时，写给对方填的问卷。
- **人工向导**：只有人能做的步骤（开面板、填密钥），生成逐步脚本。
- **没听懂重讲**：对方没接住时，补上下文用平实语言重讲一遍。
