# 隐私合规

隐私合规的工程化表达：**最小化收集、依据明确、权利可响应、全程可审计**。以 GDPR 框架为骨架，中国《个人信息保护法》同构可映射。

## 数据分级（保护强度跟数据走）

| 级别 | 例子 | 要求 |
|---|---|---|
| 基本个人数据 | 姓名、邮箱、电话 | 标准保护 |
| 敏感个人数据 | 健康、生物识别、宗教、 precise 位置 | **单独同意** + 加密 + 更严访问控制 |
| 儿童数据 | 未成年人 | 监护人同意 + 专门规则 |

## 合法依据（处理前先回答「凭什么处理」）

六种依据：同意 / 合同必要 / 法定义务 / 生命安全 / 公共利益 / 正当利益（需利益平衡测试）。纪律：

- **每个处理活动记录其依据**——说不清依据的处理就是违规处理。
- **同意的规矩**：主动勾选（不预勾选）、目的分列（一揽子同意无效）、可随时撤回且撤回路径和同意一样容易。
- 敏感数据：单独同意 + 默认不收集。

## 数据主体权利（30 天内必须能响应）

访问（给他看有什么）/ 更正 / **删除（被遗忘权）** / 限制处理 / 可携带（导出给别家）/ 拒绝。

工程含义：**这些操作必须是系统能力而非人工工程**——删除要真能删（含备份策略与下游同步）、导出要机器可读。做系统设计时就把「按用户查出全部数据、按用户删除全部数据」当内置功能规划。

## 隐私设计七原则（落地纪律）

1. **最小化**：只收集业务真需要的——「以后可能有用」不是理由。
2. **留痕**：处理活动记录（什么数据、什么目的、什么依据、存多久）+ 数据流图，审计时拿得出。
3. **加密**：静态 + 传输全程；密钥管理与数据分级匹配。
4. **访问控制**：need-to-know，敏感数据访问有审计日志。
5. **留存期限**：每类数据定义保留期并**自动执行删除**——「无限保留」是违规常态。
6. **默认隐私**：默认设置取最保护选项，收集开关默认关。
7. **跨境传输**：有合法机制（标准合同/充分性认定）才出域——先评估再传输。

## 收尾清单

数据分级映射完成 / 每个处理活动有依据记录 / 同意机制合规可撤回 / 权利响应是系统能力 / 留存期自动执行 / 敏感数据加密+审计 / 出域有机制。
