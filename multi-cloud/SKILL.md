# 多云架构

多云是高成本高复杂度的选择——先问「为什么多云」，答案决定姿势。

## 四种模式（按目的选）

1. **主备容灾**：主云跑业务、备云只做灾备（数据库跨云复制 + 自动切换）——最常见，为「云整体故障」上保险。
2. **择优组合**：各云用最强的（如 AI 训练在 A、企业应用在 B、合规数据在 C）——收益最大但运维最重，团队要真的会玩多家。
3. **地理分布**：用户就近接入 + 数据主权合规（某国数据不出境）——多区域天然多云。
4. **云中立抽象**：K8s + PostgreSQL + S3 兼容存储 + Kafka，云只当资源池——迁移自由度最高，但放弃各家托管服务的红利。

## 云中立抽象层（模式 4 的落地）

```
应用层
  ↓
抽象层：K8s（计算）/ PostgreSQL（库）/ Redis（缓存）/ S3 API（存储）
  ↓
各云托管版本（EKS/GKE/AKS…）
```

要点：抽象层选**开源标准品**（不是云专属品），基础设施全走 IaC 声明式管理——手点控制台的多云必然漂移。

## 真实成本（决策前必算）

- 多云 = 多套技能矩阵 + 多套监控 + 更复杂的网络（跨云流量费又贵又慢）。
- 「防止涨价」的锁定焦虑，常被多云自身成本吃掉——**先用抽象层拿到 80% 的自由度，别为了 20% 买下整个复杂性**。
- 没有跨云容灾演练的多云 = 双倍账单单份保险——演练才算数。

## 迁移四阶段

1. **评估**：盘点资产、理清依赖（最费时也最值——依赖图理不清迁移必翻车）、估成本。
2. **试点**：选一个非关键负载真迁移一遍，沉淀流程与坑。
3. **迁移**：增量搬、**双跑期并行验证**、数据同步先于应用切换。
4. **优化**：迁移完再缩容、上托管服务、补安全与成本治理。

## 收尾清单

目的明确（四模式对号）/ 抽象层用标准品 / IaC 全覆盖 / 双跑期并行 / 灾备演练过 / 多云成本算总账。
