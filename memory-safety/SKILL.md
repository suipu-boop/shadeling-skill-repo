# 内存安全

内存 bug 六大类，**每类有对应的结构性预防手段**——靠纪律不靠记性：

| Bug | 本质 | 结构性预防 |
|---|---|---|
| Use-after-free | 访问已释放内存 | 所有权/R lifetime |
| Double-free | 重复释放 | 智能指针（释放权唯一） |
| 内存泄漏 | 只借不还 | RAII（栈对象析构必执行） |
| 缓冲区溢出 | 写过界 | 边界检查容器 |
| 悬垂指针 | 指向已释放 | 生命周期跟踪 |
| 数据竞争 | 并发无同步访问 | 所有权/锁 |

## 安全光谱（选语言=选安全档位）

```
手动管理(C) → 智能指针(C++) → 所有权(Rust) → GC(Go/Java)
  最危险 ←————————————————————————→ 最安全
  最可控 ←————————————————————————→ 最失控
```

选型直觉：**控制要求极端的底层用 C/Rust，业务服务交给 GC 语言**——在安全与控制间取点，别在 GC 语言里怀念手动、也别在 C 里假装安全。

## RAII（资源即对象）

**资源生命周期绑定对象生命周期**：文件、socket、锁、内存——拿到即入对象，出作用域自动释放。C++ 的 unique_ptr/lock_guard、Rust 的 Drop 都是此道。纪律：

- 释放逻辑**只写一次**（在析构里），不在每个 return 分支手写 close——手写必漏一路。
- C++ 出参/传参用智能指针（unique_ptr 独占、shared_ptr 共享），**裸指针只用于「借用不拥有」**。

## 所有权思维

- 写共享数据前先答：**谁拥有它？谁只是借用？借用到什么时候？**——三问答不清就是数据竞争预备役。
- 多线程共享可变状态：要么上锁（明确锁的层级防死锁），要么改设计（消息传递/不可变数据）。
- 不可变优先：共享只读数据天然安全——能 immutable 就 immutable。

## 工具兜底（编译器之外的第二双眼）

- AddressSanitizer：内存错误检测（C/C++，编译开关即用）。
- Valgrind：泄漏与未初始化内存。
- ThreadSanitizer：数据竞争。
- Rust Miri：未定义行为检测。
- **进 CI 常态跑**（抽测或全量）——内存 bug 上线后修的代价是开发期的百倍。编译器警告零容忍：警告抓的常常就是内存 bug。
