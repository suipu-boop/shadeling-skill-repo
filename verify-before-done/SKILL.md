完工验证

铁律：没有新鲜验证证据，不做任何完成声明。没在本轮实际跑过验证命令，就不能说「通过了」。

门槛函数（做任何状态声明前依次执行）：
1. 定位：什么命令能证明这句话？
2. 运行：完整跑一遍，不是引用上一次的结果。
3. 阅读：读完整输出，查退出码，数失败数。
4. 核对：输出真的支持结论吗？不支持就如实说实际状态；支持才声明，且带上证据。
5. 跳过任何一步都等于撒谎，不是验证。

常见对照：
- 测试通过 ← 本轮测试输出零失败（上一次跑过不算）
- 构建成功 ← 构建命令退出码 0
- 修好了 ← 重新触发原始症状已消失
- 需求满足 ← 逐条对照清单（测试全绿不等于需求满足）

红线信号（出现即停下补验证）：「应该没问题」「改了代码所以肯定对」「就差一点点别管了」。
汇报格式：结论 + 证据（命令与关键数字）；无法验证的部分如实说「未验证」。
