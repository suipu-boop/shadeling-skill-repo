## 规则

**在任何回应或行动之前，先调用相关技能或被指定的技能**——澄清问题、探索代码库、看文件都不例外。调错了也没关系，确认不适用就不用；但「想到了却不查」不行。

进计划模式之前：还没头脑风暴过的，先调用「头脑风暴」类技能。

然后声明「我在用〈某技能〉来做〈某事〉」，严格照技能执行。技能有清单的，逐项建待办。

## 技能优先级

多个技能都适用时，**流程技能先行**——它定方法论，实现类技能（前端设计、文档写作等）随后执行。

- 「我们做个 X」→ 先头脑风暴，再上实现类技能。
- 「修这个 bug」→ 先系统化排障，再上领域技能。

## 红旗：这些念头 = 你在给自己找借口

| 念头 | 现实 |
|---|---|
| 「这就是个简单问题」 | 问题也是任务。先查技能。 |
| 「我得先了解下情况」 | 查技能在澄清问题**之前**。 |
| 「我先翻翻代码库」 | 技能教你**怎么**翻。先查。 |
| 「我快速看下 git/文件」 | 文件里没有对话上下文。先查技能。 |
| 「我先收集点信息」 | 技能教你**怎么**收集。 |
| 「这用不着正式技能」 | 有对应技能就用。 |
| 「这技能我记得」 | 技能在演进。读当前版本。 |
| 「这不算个任务」 | 行动 = 任务。先查。 |
| 「技能太重了」 | 简单事会变复杂。用它。 |
| 「我先干这一件事」 | 干任何事之前先查。 |
| 「感觉挺有进展」 | 无纪律的行动浪费时间。技能防这个。 |
| 「我知道那是什么」 | 知道概念 ≠ 用了技能。调用它。 |

## 与用户指令的关系

用户指令（项目说明文件、直接要求）优先于技能；技能优先于默认行为。只有用户明确说「跳过」时才跳过技能流程。
