# 脚本防御

生产脚本与「能跑就行」的差别：**出错时行为可预期**——要么安全失败、要么安全重试，绝不半途留下脏状态。

## 开头三件套（每个生产脚本第一行）

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
```

- `-e`：命令失败立即退出（不带着错误继续跑）
- `-u`：未定义变量报错（typo 不再静默成空串）
- `-o pipefail`：管道中任何一环失败整体失败
- `-E`：ERR trap 传导到函数/子壳

变量**永远加引号** `"$var"`——空格路径、空串导致的参数消失，一半的脚本事故源于裸变量。条件判断用 `[[ ]]`（词分割与 glob 免疫）。

## 错误处理

- **trap 清理**：`trap cleanup EXIT`——临时文件、后台进程、锁文件，无论成败退出时必清。
- 临时文件用 `mktemp`，绝不硬编码 `/tmp/my.tmp`（并发即冲突）。
- 失败要**说话**：结构化日志（时间戳 + 级别），失败时打「哪一步、为什么」——静默 exit 1 是排障地狱。
- 检查外部命令存在性用 `command -v`（比 which 可移植）。

## 输入验证

- 参数检查前置：文件存在可读？目录在？参数数量对？**前置失败优于中途半成品**。
- 外部输入（用户传参、环境变量、API 返回）一律当不可信：校验格式再进流程。
- 路径处理：`realpath` 归一 + 明确相对路径基准（脚本对 cwd 的假设要显式 `cd` 或校验）。

## 幂等与可重跑

**脚本要能安全地重跑**（跑挂了重跑、cron 重复触发、并发误触）：

- 目标状态检查：已存在就跳过（「不存在才创建」，不是「创建」）。
- 写操作可重入：先写临时文件再原子改名（mv），别直接改目标。
- 破坏性操作（删除/覆盖）前置确认逻辑：dry-run 模式标配——`--dry-run` 打印将做什么而不做。

## 可维护性

- 重复逻辑提函数（函数名见名知义）；常量进文件头。
- `printf` 替代 `echo`（跨平台转义行为一致）。
- 文件头注释：依赖要求、最低版本、用法示例。
- **错误路径也要测**：故意喂坏输入跑一遍——只测 happy path 的脚本等于没测。

## 收尾清单
