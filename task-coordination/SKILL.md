# 任务协同

并行开发的核心问题只有一个：**怎么切，才能各自干各自的、永不撞车**。答案是把「所有权」切成互斥块。

## 任务拆分四法

| 拆法 | 切什么 | 适用 |
|---|---|---|
| 按层 | UI / 业务 / 数据 | 全栈特性、垂直切片 |
| 按组件 | 认证模块 / 通知模块 | 模块化架构、微服务 |
| 按关注点 | 安全 / 性能 / 架构审查 | 评审、审计 |
| 按文件所有权 | 目录/模块 → 各自拥有 | **并行实现的默认** |

## 文件所有权铁律

**一个文件一个主人。** 没有例外——两个执行者改同一文件 = 合并冲突与静默覆盖的温床。

真要共改一个文件时，三条路（按优先级）：
1. **指定唯一主人**：其他人向主人提变更请求，主人串行应用。
2. **抽接口**：把共享部分抽成独立接口文件，非主人 import 接口而不改源——最推荐，冲突域直接消失。
3. **按目录重划所有权**：说明拆分粒度错了，重来。

## 依赖图设计

- **浅宽优于深窄**：A、B、C 并行 → 汇合集成，好过 A→B→C 链——链深 = 串行等待 = 并行白做。
- **关键路径决定工期**：最长的依赖链就是最短完成时间，先砍它。
- **blockedBy 从紧**：只标真依赖——「顺手先做」的假依赖是并行杀手。
- **环 = 死锁**：A 等 B、B 等 A，任务图有环立即重构拆分。

## 集成点纪律

- **接口就绪即广播**：你的产出是别人的依赖时（API 定义、类型文件、接口），完成第一时间通知下游——下游对着旧接口白干是并行开发最贵的浪费。
- 共享资源（公共类型/工具文件）变更走广播 + 明确「拉最新」指令——高频但低噪。
- 集成任务单列，预算内先联调——「各自全绿、合起来崩」的预防针。

## 收尾清单

所有权互斥（一人一文件）/ 共享走接口 / 依赖图浅宽无环 / 关键路径先处理 / 接口就绪即广播 / 集成任务单列。
