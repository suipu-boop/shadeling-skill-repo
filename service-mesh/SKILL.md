# 服务网格

服务网格 = 把服务间通信的重活（加密、重试、路由、观测）从业务代码**下沉到基础设施代理层**——应用只管说「调谁」，怎么调好是网格的事。

## 架构与选型

- **Sidecar 模式**：每个 pod 一个代理，劫持全部进出流量——通用但资源开销随规模线性涨。
- **Sidecar-less**：节点级代理/内置内核（如 eBPF 路线）——省资源，生态较新。
- 选型直觉：功能全 vs 轻量易运维是主轴——大型多集群全功能网格 vs 中小团队轻量网格，按运维能力选；**没有多集群 mTLS 和高级流量切分需求时，先别上网格**（K8s 原生 NetworkPolicy + 客户端库能覆盖的，别上重武器）。

## mTLS（零信任的地基）

- **双向验证**：A 调 B，不只 B 验 A 的证书，A 也验 B 的——服务间身份互认，任何一端被攻破都进不了对话。
- 握手五步：ClientHello → ServerHello+证书 → 客户端证书 → **双向验证** → 加密信道。
- 证书层级：根 CA（长命）→ 中间 CA（每集群）→ 工作负载证书（**短命、自动轮换**）——网格的价值就是轮换全自动，人手轮证书必出事故。
- 演进路径：先 PERMISSIVE 模式（明文+加密并存）灰度切，全量加密后切 STRICT——一把切 STRICT 是经典翻车点。

## 流量治理三件套

1. **流量切分**：按权重路由（90/10 金丝雀）、按内容路由（特定 header 走新版本）——部署管线技能里的灰度策略在网格层的实现。
2. **熔断**：连续 5xx 驱逐异常实例（自动摘除 + 冷却期回归）——断路器模式的基础设施化。
3. **每路由策略**：超时/重试按路由细配——粗粒度全局超时是既慢又脆的妥协。

## 观测（网格的免费赠品）

- 金信号四件套：**延迟 P99（>500ms 报警）/ 流量（异常检测）/ 错误率（>1% 报警）/ 饱和度（>80% 报警）**。
- 全链路 trace 自动注入（无需改业务代码）；采样生产 1-10% 足够——100% 采样是存储费无底洞。
- 指标基数要克制：标签维度爆炸 = 时序库爆炸。

## 收尾清单

上网格的理由站得住 / mTLS 双向验证+自动轮换 / 灰度切 STRICT / 切分熔断按路由配 / 金信号报警在岗 / 采样率控制成本。
