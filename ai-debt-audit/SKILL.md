# AI 债务审计

AI 生成的代码能过 happy path，但债藏在里面：没有失败路径、资源开了不关、导入幻觉出来的包。人不会犯的错 AI 高频犯——因为 AI 优化的是「看起来对」，不是「真对」。

## 什么时候用

- 一轮 AI 生成超过 20 行之后。
- 合并 AI 写的 PR 之前。
- 代码「能用但说不上哪里不对劲」时。
- Agent 宣称做完了但没给验证证据时。

## 五步定向审计

### 1. 失败模式——失败时发生什么？

- 网络超时？磁盘满？权限拒绝？空输入？
- 有 try/catch 吗？是抓**特定**异常还是全吞？
- 失败路径上资源清理了吗？（流关闭、连接归还、临时文件删除）

### 2. 孤儿资源——开了没人关？

- 临时文件、事件监听、定时器、订阅、连接——每个 open/create 都有对应的 close/dispose/remove 吗？
- 高频翻车：连接不还池、监听不注销、超时设了但没有中止清理。

### 3. 边界——什么输入会炸？

- 空数组/空串？null？几 MB 大输入？Unicode？并发调用？
- AI 几乎总是只写 happy path——边界显式补。

### 4. 幻觉依赖——导入的东西存在吗？

- 每个包真的在依赖清单里吗？
- 每个 API 方法是真的吗？AI 会编出「听起来很合理」的方法名。
- 依赖的最新版本还导出这个函数吗？（AI 常用过时 API）

### 5. 架构漂移——和项目风格一致吗？

- 错误处理风格和现有代码一样吗？
- 用的是项目既有工具函数，还是重造了轮子？
- 文件位置遵循项目约定吗？

## 红旗（见即修）

- `catch (e) {}` 或只 `console.log(e)` ——吞错。
- 开了资源却没有 `finally`。
- `// TODO: handle error` ——AI 的 「以后再说」。
- 导入项目里不存在的路径。
- 数据库连接开了没还池。

## 常见误判

- **编译通过 ≠ 正确**——编译只查语法。
- 只看 diff 不看「AI 没生成什么」——缺失的错误路径才是大头。
- 别指望垃圾回收兜底——连接、监听、定时器 GC 不管。
