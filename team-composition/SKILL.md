# 团队构成

把任务交给协作团队前先答两问：**需要覆盖哪些维度？最小几个人够？** 团队不是越大越好——每加一人，协调成本平方级涨。

## 规模启发式

| 复杂度 | 规模 | 场景 |
|---|---|---|
| 简单 | 1-2 | 单关注点、孤立 bug、小特性 |
| 中等 | 2-3 | 多文件、2-3 关注点 |
| 复杂 | 3-4 | 跨切面、大特性、深调试 |
| 超复杂 | 4-5 | 全栈特性、系统性问题 |

拇指法则：**覆盖全部所需维度的最小团队**；有富余维度的人先不加。

## 五种 preset（照抄即用）

- **评审队（3 人）**：三个评审者，维度分安全/性能/架构——多维质量把关（配合多维评审技能的去重汇总）。
- **调试队（3 人）**：三个调查者各领一个竞争假设——假设竞速（六类失败模式各领一路）。
- **特性队（1+2）**：一个领队拆任务管集成，两个实现者按文件所有权并行——所有权铁律见任务协同。
- **全栈队（1+3）**：领队 + 前端/后端/测试三个实现者——按层拆分，接口契约先行。
- **调研队（3 人）**：各领一个调研问题并行（代码库摸底/库对比/方案收集）——产出汇总成决策材料。

## 生命周期

1. **成立**：按 preset 组队，每人明确职责、维度/假设/所有权，**对外接口契约先定**（谁给谁什么、什么格式）。
2. **运行**：沟通纪律（见下）；进度在里程碑点检查，不做逐分钟盯梢。
3. **收队**：任务完成立即缩减——挂着不用的人是纯成本；产出与教训归档。

## 沟通纪律（简版）

- **默认点对点**：消息只发给需要的人——广播是稀缺资源，只留给影响全队的阻断事件。
- **接口就绪即通知**：你的产出是别人的输入，完成第一时间说。
- **状态走任务系统**：别用聊天刷状态，任务状态机是事实源。
- **集成点必同步**：到达集成里程碑时全队对齐一次。

## 反模式

- 全员广播刷屏（信噪比崩塌）
- 没有契约就开工（下游对旧接口白干）
- 任务完了不解散（资源空转）
- 领队亲手写码（领队的产出是决策与集成，写码是逃避协调责任）

## 收尾清单

规模最小覆盖 / preset 对号入座 / 契约先行 / 点对点默认 / 接口就绪即通知 / 完成即收队。
