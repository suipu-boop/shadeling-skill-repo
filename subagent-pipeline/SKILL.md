把计划交给流水线执行：每张工单派一个**全新**的实施子代理，每张工单之后做一次任务审查（规格符合 + 代码质量），最后做一次全分支的宽口径终审。

**为什么用子代理：** 你把任务委派给带隔离上下文的专职代理。精心构造它们的指令与上下文，它们就聚焦、就成功。它们绝不继承你会话的上下文或历史——你构造的正是它们需要的东西。这也保住了你自己的上下文留给协调。

**核心原则：** 每任务全新子代理 + 任务审查（规格 + 质量）+ 终审 = 高质量、快迭代。

**叙述纪律：** 工具调用之间最多说一行——台账和工具结果才是记录。

**连续执行：** 任务之间不停下来请示。四种情况之外一概不停：不可逆/破坏性操作；安全敏感动作；工作区之外需要先打招呼的副作用（合并、推共享分支、发布）；计划烂到每条路都是猜。其余全靠裁决推进。

**裁决而非停摆。** 运行中的计划不等人类。冲突、歧义、计划缺陷、本想请示才超的限额——你定。规格是约束性权威，计划是它的论证，两者都没说的靠你的判断。每个决策记进台账：`Ruling: <定了什么> — <为什么> — <错了的代价>`，然后继续。

## 什么时候用

- 有实施计划，任务基本独立 → 本技能
- 任务紧耦合 → 先「头脑风暴」或拆计划，别硬上
- 会话里没有子代理工具 → 用「计划执行」（原生内联）技能

**对比内联执行：** 每任务全新子代理（无上下文污染）+ 每任务审查；代价是每任务每审查一个新上下文。内联省上下文但只在最后审一次。

## 设置

- **隔离工作区：** 用「隔离工作区」技能建一个或确认已有。未经用户明确同意，绝不在 main/master 上直接开工。
- **台账：** 每份计划有自己的工作区目录（git 忽略的暂存区）。开工时先找这份计划的台账 `progress.md`：首行是本计划文件名 → 写着 `Task <N>: complete` 的工单**已完成，绝不重派**，从第一张没完成的工单续跑；末行停在修复轮的 = 循环中，从下一轮续。首行是别的计划 → 别动它，自己建新的。台账首行：`# SDD ledger — plan: <计划文件路径>`。
- **压缩后恢复：** 对话记忆过不了压缩。真实会话里丢过位置的控制器把整段已完成的工单重派了一遍——观测过的最贵失败。进度记在**台账文件**里，不只记待办。压缩之后，信台账和 `git log`，别信自己的回忆。
- **读计划：** 通读一遍，记下上下文和全局约束，每张工单建一个待办。计划指了规格就把规格也读了：规格是权威，计划内部冲突以规格为准。无规格的计划在台账记一笔，没有规格时的裁决都是临时的。
- **开工前冲突扫描：** 派工单 1 之前通盘扫一遍：互相矛盾的工单、违反全局约束的工单、计划明确要求但审查标准视为缺陷的东西。产出是一张**表**：每对共享文件/接口的工单一行（谁产出什么、谁消费什么、发现了什么），每张工单一行（自洽性：它指定的测试对它指定的代码、建的文件对后文碰的文件）。「扫过了很干净」但没有这些行的，等于没扫。表写进台账，发现的东西逐条按计划文本裁决并记录，然后派工单 1。

## 模型选择

每个角色用能胜任的最弱模型：省成本、提速度。

- **机械实施**（隔离函数、规格清晰、1-2 个文件）：快而便宜的模型。计划写得够细时多数工单都是机械活。
- **整合与判断**（跨文件协调、模式匹配、排障）：标准模型。
- **架构与设计**：最强模型。全分支终审算这类——派最强模型，不是会话默认。
- **审查任务**：按 diff 的规模、复杂度、风险配模型。小的机械 diff 不需要最强模型；微妙的并发改动需要。小修复 diff 的定向重审用中低档。
- **修复循环升级（4-5 轮）**：至少高一个档位的模型。

## 流程

### 1. 派实施者

派发前先记 BASE（`git rev-parse HEAD`）——审查包和修复轮 diff 都要用。

**工单简报：** 派发前把该工单的完整文本提取到独立文件（简报文件），打印路径。派发内容包含：(1) 一行话说明这张工单在项目里的位置；(2) 简报路径——「先读它，这是你的需求，其中的精确取值逐字照用」；(3) 简报不可能知道的、来自先前工单的接口与决策；(4) 你注意到的简报歧义的裁决；(5) 报告文件路径与报告契约。精确取值（数字、魔法串、签名、测试用例）只出现在简报里。**绝不让子代理读整份计划。**

**报告文件：** 按简报命名（`…/task-N-brief.md` → `…/task-N-report.md`），路径写进派发提示词。实施者把完整报告写进文件，只返回：状态、提交、一行测试摘要、疑虑。

**派发只装一张工单，不是会话历史。** 别把先前工单的总结（「工单 1-3 之后的现状」）粘进后面的派发——真实会话里一份派发 42k 字符、99% 是粘的历史。新子代理需要：它的工单、它碰的接口、全局约束。没别的。

**派发自带禁派契约：** 实施者绝不派子代理——不打下手，更不派审查者。审查由你在报告之后安排。真实会话里，工人自己派的每个审查者都在重复控制器要派的那个审查。

先前的工单在被触碰的区域留了搁置发现的，派发里带上那条台账的指针。

**记下实施者的代理标识**——修复轮 1-3 要续它。

**绝不并行派多个实施子代理**（会冲突）。

**等待子代理：** 别用短超时轮询，也别无限期干等。有本地活（记台账、打包下一轮审查、读报告）就干活，子代理结果自然会来。真闲着就分段限时等待（五到十分钟，平台允许的话），段间发一行状态并核对活着的子任务：列出来，追任何跑完没报的。

### 2. 处理报告

实施者报告四种状态之一：

- **DONE：** 生成审查包（BASE..HEAD 的完整 diff 存成一个文件），派任务审查者。审查包文件让审查者一次读取拿到提交清单、stat 摘要和带上下文的全量 diff——别让审查者自己用 git 命令重新推导。用你派实施者**之前**记的 BASE，绝不用 `HEAD~1`——多提交的工单会被静默截断。绝不派没有 diff 文件的任务审查。
- **DONE_WITH_CONCERNS：** 活干完了但有疑虑。先读疑虑再前进——疑虑里常埋着真问题。
- **NEEDS_CONTEXT：** 缺信息。补上下文，原样重派。
- **BLOCKED：** 干不了。评估：上下文问题 → 补上下文重派；需要更强推理 → 换更强模型重派；任务本身有毛病 → 回计划修。

### 3. 任务审查（规格 + 质量）

审查者收三个路径（同一简报文件、报告文件、审查包）外加**全局约束块**。约束块是审查者的注意力透镜：从计划的全局约束或规格里**逐字**照抄约束性要求——精确取值、精确格式、组件间声明的关系（「与 X 同布局」「匹配 Y」）。模板自带流程规则（YAGNI、测试卫生、审查方法）——约束块只放**本项目规格**要求的东西。

**三不：** 不加没有具体任务理由的开放式指令（「检查所有用法」「有空跑跑竞态测试」）；不让审查者重跑实施者已经跑过的同一批测试——实施者的报告就是测试证据；**不替审查者预判**——绝不让审查者「别标记 X」「至多算 Minor」。觉得某发现是误报，让它提出来，你在审查循环里裁决。提示词里冒出「不要标记」「别当成缺陷」——停下：你在预判，通常是为了省自己的审查循环。

审查者可能报「⚠️ diff 里验证不了」项——需求在被改代码之外、或横跨多张工单。这些不阻塞审查其余部分，但你必须在标记工单完成前逐项自己解决：计划和跨工单上下文在你手里。确认真缺口 = 规格审查不通过，进修复循环。

### 4. 修复循环

触发条件：规格 ❌、任何 Critical/Important 发现、或你确认属实的 ⚠️ 项。

**循环之外先分流两件事：**
- **Minor 发现**随手记台账（`Task <N>: minor (deferred): <一句话>`），并让终审盯着这份清单分流哪些必须合并前修。没人读的汇总就是静默丢弃。Minor 永不进循环。
- **计划强制的发现**（或与计划文本冲突的发现）归你裁决：发现对照计划文本，以规格为权威定夺，台账记录后才动手。不因为「计划就这么写的」而无视发现，也不在没有记录裁决的情况下派与计划矛盾的修复。

其余全进循环。一轮修复 = 一次修复派发 + 一次定向重审。**每张工单最多五轮：**

- **1-3 轮——续原实施者。** 把未决发现逐字发回。它的上下文还在：知道工单、代码、自己的选择。平台不能给活着的子代理续消息的，派新实施者，带上简报路径、报告文件路径和发现——报告文件就是持久记忆。
- **4-5 轮——派全新实施者 + 更强模型。** 附上背景：「此前实施者试过 [N] 次，现在归你了。先读报告文件了解试过什么。」撑过三轮续命的循环，通常说明实施者看不见自己的问题——换新眼 + 升能力，一步到位。

**每轮都要：** 实施者修复、重跑覆盖被改代码的测试、把修复报告追加到同一报告文件、返回短契约。重派审查前确认修复报告里有：覆盖测试、跑的命令、输出——三样齐了才重审。修复消息里点名覆盖的测试文件——一行修复不需要全套。

**重审是定向的：** 审查范围 = 修复 diff（FIX_BASE = 上次审查看到的头）。重审者对每条发现判 ADDRESSED / NOT ADDRESSED，只对修复 diff 里的新破坏报警。修复 diff 里的新 Critical/Important 并入未决清单。范围外的观察记台账当延期 minor——绝不延长循环。

**每轮之后记台账：** `Task <N>: fix round <R>/5 (<X> 项已解决, <Y> 项未决 — <发现一句话>; commits <a7>..<b7>)`

**绝不自己在控制者会话里修发现**——你的上下文留给协调，而且控制者的修复跳过了审查。

**熔断器：** 第 5 轮重审仍有未决发现——停止派发，逐条亲自裁决：
- **审查者错了 / 可争论：** 搁置——`Task <N>: parked — <发现> — Ruling: <代码为何站得住>`。终审会看到双方。
- **真问题但下游不依赖：** 同样搁置，裁决写明「真实但延期」。
- **真问题且承重**（后续工单压在上面 / 揭示计划缺陷）：裁决出解锁依赖工作的最小改动，台账记录，带进下一张工单的派发。结构坏了还静默搁置，等于让每张后续工单压着它盖楼。只有当缺陷让每条路都是猜时才停。

**只在熔断时裁决。** 提前裁决收尾循环 = 换个名字的预判。每次裁决都是台账条目——静默丢弃被禁止。

### 5. 完成工单

审查干净——或熔断后所有未决发现都已带裁决搁置——在同一批记账里追加：

- `Task <N>: complete (commits <base7>..<head7>, review clean)`
- `Task <N>: complete (commits <base7>..<head7>, <K> parked)`

标记待办完成，进下一张。**绝不带着未修复也未搁置的 Critical/Important 进下一张工单。**

## 终审

全部工单完成后，对整条分支做一次宽口径审查：审查包 = 合并基到 HEAD 的完整 diff，派**最强可用模型**，用「主动求审」的审查提示词模板，并指向台账里所有延期 minor 和 parked 行，让它分流哪些必须合并前修。

终审返回发现：派**一个**修复子代理带完整清单——不是一个发现一个修复者。按发现逐个派修复者各自重建上下文重跑套件；一次派发一份清单又快又省。修复后做一次定向重审，残余发现逐条裁决。终审干净：删掉这份计划的工作区（记录已活在 git 里），用「分支收尾」技能整合。

## 借口表

| 借口 | 现实 |
|---|---|
| 「任务简单，我自己顺手修了」 | 控制者修复跳过审查。你的上下文留给协调。 |
| 「并行派实施者更快」 | 多个实施者编辑同一仓库 = 冲突地狱。一次一个。 |
| 「审查者要求很蠢，跳过这轮」 | 对审查结果的异议走裁决，不走跳过。记录裁决。 |
| 「五轮太多，三轮就该熔断」 | 提前裁决 = 换名的预判。熔断器是保险丝，不是调速旋钮。 |
| 「台账回头补」 | 压缩一来，没记的进度等于没发生。重派整段已完成的工单是最贵的失败。 |
