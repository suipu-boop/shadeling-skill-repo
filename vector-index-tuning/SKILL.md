# 向量索引调优

## 先按规模选索引（别一上来就调参）

| 数据量 | 索引 | 理由 |
|---|---|---|
| < 1 万 | **Flat（暴力精确）** | 全量扫描 100% 召回，小数据直接用，别建索引 |
| 1 万-100 万 | **HNSW（图索引）** | 对数级检索，95-99% 召回，最常用 |
| 100 万-1 亿 | HNSW + 量化 | 图索引 + 压缩向量省内存 |
| > 1 亿 | IVF+PQ / DiskANN | 量化分桶或落盘，牺牲部分召回换规模 |

**从小索引起步、有痛再换**——过早优化索引是向量检索最常见的浪费。

## HNSW 三参数

| 参数 | 默认 | 作用 |
|---|---|---|
| M（每节点连接数） | 16 | 越大召回越好、内存越多 |
| efConstruction（建图候选） | 100 | 越大索引质量越好、建得越慢 |
| efSearch（检索候选） | 50 | 越大召回越好、查得越慢——**运行时调它平衡召回/延迟** |

调参顺序：efSearch 是线上旋钮（随时可调），M 和 efConstruction 是建库决定（改了要重建）——先动线上旋钮，不够再重建。

## 量化（内存翻倍省）

| 方案 | 每 512 维向量 | 代价 |
|---|---|---|
| FP32 全精度 | 2KB | 基准 |
| FP16 半精度 | 1KB | 几乎无损 |
| INT8 标量量化 | 512B | 召回略降 |
| 乘积量化 PQ | ~32-64B | 召回降，配合重排救回 |

组合拳常用：**量化索引粗召回 + 原始向量精排**——内存省 4-8 倍，质量靠重排拉回。

## 运维纪律

- **真实查询压测**：合成数据测出的参数不算数——分布不同召回差很远。
- **召回率持续监控**：数据漂移（增量插入后）召回会退化，用金标查询集定期回归。
- 建索引时间也是成本：更新频繁的集合要算「重建窗口」。
- 冷启动预热：冷索引首批查询巨慢，上线前预热（自动跑一批查询把热数据带进内存）。
- 分层存储：热数据内存、冷数据磁盘，按访问模式分。

## 收尾清单

规模档位对号 / efSearch 先调 / 量化配重排 / 真实查询压测 / 召回率回归在跑 / 预热做过 / 重建窗口有预算。
