# 模型发布门禁

训练顺利 + 目标指标变好 ≠ 可以上线。四道门禁逐道过，**任何一道不过就停**。

## 第一道：数据质量门

碰评测之前先查训练集：去重做了吗？**金标集泄漏**了吗（评测题混进训练数据 = 后面全部白测）？标签噪声抽检过吗？在泄漏数据上训出的模型，后面三道全作废。

## 第二道：能力漂移门

用冻结的漂移套件（通用能力 + 邻近领域样本）重跑 checkpoint，与基线逐项对比。设**漂移预算**：目标任务外的能力（推理、指令遵循、邻近领域）允许小幅波动、不允许塌方——**灾难性遗忘**是微调最阴的暗伤：目标分涨了，模型变笨了没人发现，直到用户投诉。

## 第三道：与基座对比门

checkpoint vs 基座模型，同一批 prompt 成对对比（裁判评分时位置随机化防位置偏差）。铁律：**holdout 赢了但实战对比输了 = 不发布**——两处判定必须一致才放行，只在冻结金标上赢是过拟合的典型症状。

## 第四道：导出与冒烟

发布格式按部署面选，不按习惯选：

| 目标 | 格式 |
|---|---|
| 数据中心 GPU 服务 | FP8（新 GPU 默认）/ AWQ INT4（旧 GPU） |
| 本地/CPU 部署 | GGUF（Q4_K_M 起步） |

- **冒烟测试必做**：导出前后各跑 3-5 条金标输出做 diff——量化把模型导坏是真实事故，不测不知道。
- 导出物连同冒烟 diff 报告一起归档；测试集与训练环境隔离。

## 判定与记录

每道门禁留书面证据（数字、diff、抽检记录），终局结论只有两个：**发布**或**拒绝**。拒绝不丢人——上线一个遗忘症模型才丢人。被拒的 checkpoint 回炉（加数据/调参/缩目标），用同一套门禁重验。

## 收尾清单

数据门查过泄漏 / 漂移预算内 / 与基座实战对比一致 / 导出冒烟 diff 干净 / 证据归档 / 判定二元不留灰区。
