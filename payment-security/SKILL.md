# 支付安全

支付安全的总纲：**你的系统碰卡数据越少越安全、越便宜**——终极形态是卡数据完全不经过你的服务器（令牌化出域），合规范围收缩到近乎零。

## 数据三段规则（PCI 核心）

| 段 | 数据 | 规则 |
|---|---|---|
| **禁存** | 磁道数据、CVV/CVC、PIN | **任何形式都不许存**（含日志、备份、临时文件） |
| 可存（需加密） | 卡号 PAN、持卡人名、有效期 | 强加密存储 + 展示脱敏（前 6 后 4） |
| 出域 | 全部卡数据 | 客户端直连支付网关，服务端只收 token |

**日志是高危盲区**：请求体、异常堆栈、调试输出都可能夹带卡数据——日志管道必须配敏感字段清洗，「禁存 CVV」要写进代码规范和 review 检查项，靠自觉必漏。

## 令牌化架构（标准解）

```
客户端 ──卡数据──> 支付网关（返回 token）
客户端 ──token──> 你的服务器 ──token──> 网关扣款
```

- 服务端只见 token：泄漏了也没有卡数据——**默认全走这条路**（托管收银台/支付组件让卡数据直进网关）。
- 订阅续扣：存网关的支付方式 ID，不存卡——退订换卡都走网关 API。
- 自建令牌库（仅当必须自持卡数据）：随机 token + AES-256-GCM 加密映射，**密钥与密文分离存放、密钥走密钥管理服务**——密钥和密文同库存放等于没加密。

## 传输与存储底线

- 传输：TLS 1.2+ 全站强制（含回调地址与 webhook 端点）；Cookie 安全属性全套（Secure/HttpOnly/SameSite）。
- 存储：卡号类数据 AES-256 级别加密 + 密钥轮换预案；数据库访问最小权限（need-to-know）。

## 合规分级与范围收缩

PCI 分级按年交易量（>600 万笔 Level 1 要年度外审；量越小自评问卷越简）。**降级路径 = 架构级范围收缩**：令牌化 + 托管收银台让卡数据不过手，最重的合规义务直接消失——这是架构决策（做系统设计时定），不是合规部门事后能补救的。
