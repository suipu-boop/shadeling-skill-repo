# 微调决策路由

先问一个大部分微调项目跳过的问题：**真的需要训练吗？** 多数「微调这个」的诉求，有更便宜更好的答案。

## 先下匝道（off-ramps）

- **知识型问题且事实常变**（价格、文档、新闻）→ **RAG**。微调把知识Snapshot进权重，事实一变就过期；RAG 换检索库就行。
- **行为还在摸索、时常要调** → **提示工程**。微调锁死行为，没稳定的别锁。
- **稳定且体量大的领域知识** → 才考虑继续预训练（CPT）。体量判据：

| 领域文本量 | 路线 |
|---|---|
| < 10MB | 纯 RAG |
| 10-500MB | RAG + 微调 |
| 500MB-10GB | CPT → SFT |
| > 10GB | CPT 必选 |

CPT 学习率约为预训练学习率的 10%。

## 方法路由（确认真要训之后）

| 手里有什么 | 路线 |
|---|---|
| 输入/输出示范对 | SFT（监督微调） |
| 偏好对（A 好于 B）/ 点赞点踩 | 偏好优化（DPO 族） |
| 可验证的通过/失败信号 | 强化式训练（RLVR 类） |
| 还没有评测集 | **停**——先建评测（见微调评测先行） |

## 偏好优化的细分选择

- **DPO** 是安全默认：β≈0.1，学习率 5e-7~1e-6，1-2 轮。学习率比产出该 checkpoint 的 SFT **低**——把 SFT 尺度的学习率搬进 DPO 是最常见配置事故。
- **ORPO**：内存紧张或没有独立 SFT checkpoint 时——免参考模型，SFT+偏好一锅出。
- **KTO**：反馈是不配对的点赞/点踩时——别硬凑合成对数据去喂 DPO。
- 经典 RLHF（奖励模型+PPO）在生产管线已退役：以上方法都更便宜更好维护。

## 训练前自检

- 评测集建好了吗（没有就停）？
- off-ramp 排除了吗（RAG/提示工程试过吗）？
- 数据格式与目标方法匹配吗？
- 基座模型的规模档位与任务复杂度匹配吗（小任务别上大模型）？

## 收尾清单

off-ramp 逐项排除 / 路由有据（手里数据形状决定方法）/ 评测先行确认 / 学习率按方法校准 / CPT 仅限大体量稳定知识。
