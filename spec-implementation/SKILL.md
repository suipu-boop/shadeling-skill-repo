你手里有一份规格，规格下挂着若干工单，工单描述怎么把它实现出来。

目标：整个规格在一条**集成分支**上实现完毕，每张工单都以你们的工单系统关单的方式收口。

工单不是步骤清单，是**任务图**：工单之间有阻塞关系。任何时刻都存在一个**前沿**——当前就绪、可以开工的工单集合。

与子代理的通讯要稀疏：主要传**上下文指针**（规格、工单、调研笔记、先前提交的路径），不复制指针里已经有的信息。

**实施子代理**尽量后台跑，并发拉满。

## 步骤

1. 读规格和工单，理清任务图。

2. （可选）派**探索子代理**做工单要求的侦查——相关代码文件或外部文档。确保探索子代理能存文件：笔记存在仓库外、所有后续子代理都能访问的目录里。这样**实施子代理**可以专心实施，不做侦查。

3. 建集成分支。若工单系统走 PR 关单（或用户要 PR），在第 5 步首次合并后开草稿 PR（领先 main 零提交的分支开不了 PR），标注本 PR 关闭哪些规格与工单。

4. 派**实施子代理**逐工单实施，每个工单在自己的 worktree、自己的分支上。每个实施子代理：
   - 开工前确认自己的 worktree 基于集成分支，不是就重置过去；
   - 调用「测试先行」技能建该工单；
   - 报告完成前，把集成分支的顶端合并进自己的分支。

5. 实施子代理完成后，派**合并子代理**把它的成果合进集成分支。

6. 合并改变了**前沿**（新工单就绪了），就再派实施子代理开工新工单——并发就是这样滚起来的。

7. 全部工单完成后，对集成分支调用「双轴代码审查」技能。审查提出的问题由**一个**实施子代理统一修掉。

8. 有草稿 PR 就转正式待审；没有就按工单系统的关单方式逐张关单，报告集成分支。

9. 清理所有实施子代理的 worktree。
