# 服务韧性

分布式系统里依赖必挂：网络会超时、下游会过载、机房会断电。韧性的目标不是不失败，而是**失败时体面**：自己不倒，用户有交代，恢复后自动回。

## 错误先分类，再选策略

- **可恢复**：网络抖动、限流、文件暂缺——重试有意义。
- **不可恢复**：内存耗尽、栈溢出、程序 bug——重试无意义，快速失败。
- **预期失败**：校验不通过、余额不足——这是业务结果，不是故障。

## 五件套

### 1. 重试 + 指数退避

- 只重试**幂等**操作（下单、扣款要先保证幂等再重试）。
- 退避：1s → 2s → 4s，加随机抖动（jitter）防惊群。
- 上限 3 次左右；带重试预算（全局重试占比超 10% 就停止重试，防止重试风暴）。

### 2. 超时

- **每个外部调用必须有超时**，默认值是不设防。
- 超时层层传递：上游总超时 = 各下游超时之和的余量内。
- 连接超时短（秒级）、读超时按业务设。

### 3. 熔断器

三态：**闭合**（正常放行）→ 错误率超阈值 → **打开**（直接快速失败，不打下游）→ 冷却期后 → **半开**（放几个探测请求，成功则闭合，失败再打开）。

不给下游喘息的重试就是 DDoS 自己人。熔断打开时的快速失败要给清晰错误信息。

### 4. 优雅降级

依赖挂了给「差但可用」的答案：
- 推荐挂了 → 返回热门榜；评论挂了 → 只显示主内容。
- 降级要在设计期定好，不是事故现场现想。
- 降级动作要可观测（打了降级标签的响应要能统计）。

### 5. 舱壁隔离

资源按依赖分池：A 服务占满连接池不能拖死 B 服务的调用。每类依赖独立超时、独立重试预算、独立并发上限。

## 落地纪律

1. 失败路径写测试：mock 依赖超时/5xx，验证熔断和降级真的生效。
2. 一切保护措施都带指标：重试率、熔断状态、降级触发次数。
3. **Fail fast 优先**：入口先校验，坏请求秒拒，不带病深入。
4. 吞错是原罪：要么处理、要么带上下文上抛，永不静默。
