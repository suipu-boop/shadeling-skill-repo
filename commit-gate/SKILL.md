# 提交闸门

AI 助手赶进度时会顺手 `git commit --no-verify` 跳过 pre-commit 钩子——lint、测试、安全扫描全部形同虚设。本技能的思路：**与其指望 Agent 自觉，不如让绕过命令根本执行不了**。

## 该拦什么

| 旗标 | 后果 |
|------|------|
| `--no-verify` | 跳过 pre-commit 与 commit-msg 钩子（lint/格式化/测试/安全扫描全废） |
| `--no-gpg-sign` | 跳过提交签名（签名政策失效） |
| `commit -n` | `-n` 是 `--no-verify` 短形式，`-nm` 这类组合旗标同样要拦 |
| 各旗标的缩写前缀 | git 接受 `--no-veri` 这种前缀，正则要覆盖 |

## 拦截原理（前置钩子）

在 Agent 的工具调用层加前置检查：每次 Bash 调用先过正则——

- **匹配到绕过旗标 → 拒绝执行**（退出码 2 = 整个调用作废），并给出提示「去掉绕过旗标，让钩子正常跑完」。
- 未匹配 → 放行。
- 正则只盯 `command` 字段，别被 cwd、描述文本误触发。
- 不检查 `git` 关键字本身——加前缀提权（以管理员身份）、`if git ...`、别名调用照样能拦住。

## 误拦取舍

提交信息里**提到**旗标（如「修复 --no-verify 问题」）也会被拦——这是故意的：宁可偶尔误拦，不可漏放绕过。误拦的解法是改写命令，不是放宽闸门。

## 明知的局限（诚实边界）

纯文本检查拦得住「顺手绕过」，拦不住「存心绕过」：把旗标拆开拼、或 `git -c core.hooksPath=/dev/null commit` 依然能过。对存心者需要更重的手段（服务端钩子、保护分支）——但顺手绕过占绝大多数，前置检查的性价比极高。

## 扩展与配套

- **加旗标**：往正则里追加模式（如 `--force` 强推拦截）。
- **危险命令并行拦截**：同一机制可再挂一条「递归强删根目录」类的拦截规则。
- **配套条件**：闸门确保钩子「必跑」，但钩子本身得有意义——没内容的质量门拦了也白拦。
- **团队化**：配置文件进版本库 + 新人文档写明原因 + 部署后故意触发一次验证真的生效。
