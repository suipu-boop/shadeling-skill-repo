# 嵌入选型

嵌入质量 = 检索质量的地基。模型选错、分块乱切，后面重排做得再花也救不回来。

## 模型选型四维

| 维度 | 判据 |
|---|---|
| 任务类型 | 通用文本 / 代码检索 / 领域文档（金融/法律有专用模型）——专用模型在自家领域显著更强 |
| 上下文长度 | 模型 max tokens 决定单块上限——长文档要配长上下文模型 |
| 部署方式 | API（省心、按量付费）vs 本地开源（数据不出门、无边际成本）——数据敏感度先定这步 |
| 多语言 | 跨语言检索必须多语言模型；纯中文场景中文优化模型常更强 |

通用纪律：**用检索基准（MTEB/C-MTEB 类榜单）按自家任务类型筛短名单，再用真实数据 A/B 定案**——榜单分高 ≠ 你家数据上分高。

## 分块策略（最常见的翻车点）

- **按语义边界切**：段落/章节/函数为单位，别按字符数硬切——把一句话切成两半，两半都废。
- 块大小 200-500 token 起步，**带 10-20% 重叠**防边界信息丢失。
- 太碎 = 上下文丢失；太整 = 噪声稀释——用检索评测集定案（见微调评测先行的金标思路，这里同理建一套检索金标）。
- 元数据跟着块走：来源、章节、时间、权限——过滤和排障全靠它。

## 管线纪律

- **归一化**：用余弦相似度就把向量归一化（否则度量失真）。
- **批量嵌入**：一批一批打，别一条一条请求——吞吐差一个量级。
- **缓存嵌入**：静态内容嵌入结果存下来——重复计算是纯浪费。
- **模型不混用**：一个检索系统一套嵌入模型——不同模型的向量空间不兼容，换了模型**全库重嵌**。
- 预处理别跳过：清理格式噪声、去重、规范编码——垃圾进垃圾出。

## 收尾清单

按任务类型筛短名单 / 真实数据 A/B 定案 / 语义分块带重叠 / 元数据齐 / 归一化+批量+缓存 / 模型唯一且版本受控。
