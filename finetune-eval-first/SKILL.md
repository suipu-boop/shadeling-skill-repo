# 微调评测先行

铁律：**没有评测集，就没有微调**。没有它，训练无从对比、回归无从发现、数据无从标注——评测集既是标尺又是训练数据源。

## 飞轮八步

1. **收集轨迹**：生产/agent 的真实运行记录；没有就用合成任务起步。
2. **错误分析**：≥100 条真实轨迹，先开放式标注（读轨迹、用自己的话记失败原因），再聚类成 **4-8 个失败桶**——少于 4 说明读浅了，多于 8 该合并。
3. **每桶一个评分器**：确定性评分优先（精确匹配、规则校验）；真正主观的标准才用校准过的 LLM 裁判。
4. **排优先级**：频次 × 严重度 × 业务价值。
5. **标注轨迹进训练数据，留出 holdout**：金标集条目按 ID 排除在训练集外——漏排 = 数据泄漏，全部指标作废。
6. 训练。
7. **用同一套评测**重跑 checkpoint——不许换更松的标尺。
8. 新失败模式回流第 2 步——飞轮转起来。

## 金标集构建

- **有轨迹**：走错误分析路线（上面 2-3 步），金标 = 各失败桶的代表性样本 + 做对的样本。
- **没轨迹**：按维度合成——枚举关键轴（任务类型、难度、边界、用户画像），交叉采样，别只生成「正常路径」。

## 评分器设计

- **确定性优先**：能写规则/断言的绝不请 LLM——快、稳、免费、可复现。
- **LLM 裁判要先校准**：与人工评分对齐（相关性达标）才能上岗；位置偏差（候选顺序影响打分）靠交换顺序取均值消。
- 评分器是**代码**：进版本库、走评审、随评测集一起演化。

## 基线与漂移套件

- **训前先测基线**：当前模型（未微调）在金标集上的成绩——没有基线，「提升了」无从谈起。
- **漂移套件**：除目标任务外，加测通用能力（推理/指令遵循/邻近领域）——微调常见的暗伤是**灾难性遗忘**：目标任务涨分、其他能力塌方。漂移套件就是防塌的体检。
- 套件冻结版本，与基线一起存档；checkpoint 出炉用同一套重跑对比。

## 收尾清单

≥100 条真实轨迹读完 / 失败桶 4-8 个 / 每桶有评分器 / LLM 裁判已校准 / 金标 ID 已从训练集排除 / 基线与漂移套件已冻结。
