# 云成本优化

成本治理四步框架（各云通用，厂商细则按此映射）：

## 1. 可见性——看不见就省不了

- **成本分配标签强制化**：环境/项目/成本中心/负责人/管理方五要素打全——没有标签的账单是糊涂账。
- 预算告警：月预算 80% 预警、100% 告警，别等账单来了才发现。
- 成本异常检测开启：环比突增自动报警（配置错误一晚上烧掉一个月预算的常见剧本）。

## 2. 缩容（Right-Sizing）

- **看利用率再定规格**：CPU/内存长期 <20% 的实例就是缩容对象——最大的一块肥肉通常在这里。
- 自动伸缩代替按峰值配置：峰值是尖的，钱该按平均花。
- **清僵尸**：闲置的磁盘、旧快照、没人挂载的 IP、测试环境的「临时」资源活了一年的——每月定期扫一次。
- 生命周期策略：日志/备份转低温存储（30 天转低频、90 天转归档、365 天过期）。

## 3. 定价模型——为确定性付低价

| 用法 | 买法 | 折扣量级 |
|---|---|---|
| 常年在线的稳定负载 | 预留/包年 | 30-70% |
| 可中断的批处理/CI | 竞价实例 | 60-90%（会被驱逐，只给无状态） |
| 稳定但规格常变 | 节省计划 | 40-66% |

原则：**稳定负载买预留、弹性负载用竞价、关键服务留按量兜底**。竞价实例必须容忍中断（检查点/重跑），数据库别上竞价。

## 4. 架构级优化

- 托管服务替代自运维：省的不只是钱，还有运维人力。
- 缓存降读取成本：热点数据进缓存，数据库和出口流量一起省。
- **数据传输是大头**：跨区/跨云流量费远超计算费——架构上把「说废话的流量」消掉（就近缓存、压缩、减少跨区调用）。
- 观测自己的成本：成本仪表盘进周会——成本是持续工程，不是一次性项目。

## 收尾清单

标签五要素全覆盖 / 预算+异常告警在岗 / 利用率扫过僵尸清过 / 稳定买预留弹性用竞价 / 生命周期策略配好 / 成本看板进例会。
